## 3. プレイヤー移動
- `CharacterBody3D` + `CollisionShape3D`（カプセル推奨）、物理処理は `_physics_process(delta)` 内。`move_and_slide()` を使用。
- カメラの前方をXZ水平面に投影して正規化し、入力をカメラ相対ワールド方向へ変換。カメラ回転後もWが画面奥方向を意味する。
- 移動速度 **5.0 m/s**、加速度 **22 m/s²**、減速度 **30 m/s²** は仮。重力 **20 m/s²**、ジャンプ初速 **7.0 m/s**、最大登坂角 **40°**。
- ジャンプは地上または許可されたコヨーテ時間内のみ。空中二段ジャンプは禁止。コヨーテタイム **0.10秒**、ジャンプ入力バッファ **0.12秒** を初期値として試験。空中での方向制御 **地上の70%** は仮。M03では加速度・減速度への係数とし、最高水平速度は地上と共通。ジャンプ押下を1回だけ消費し、長押しによる自動再ジャンプは行わない。
- 自動ステップ登り・移動床・汎用リスポーンは後続チケット。M03ではテストマップ専用の最小落下復帰を実装し、仮の判定高度Y=-10mより下でPlayerSpawnへ戻す。復帰時は速度とジャンプ受付を初期化し、ジャンプの再押下を必要とする。
- FREEでは既存移動・ジャンプを維持。新戦闘の接近・攻撃中の方向入力は対象を向いた単発ステップ要求としてM08で扱う。通常移動との競合・空中からの開始条件・割込み時点は試作で検証する。
- 8方向とは**スプライトの向き**の概念。移動方向はアナログで360度、8方向アニメーションに量子化する。

## 5. 2Dスプライトと3D衝突
- プレイヤー本体のコリジョンは3D。表示は `AnimatedSprite3D` を子に置き、アニメーションと見た目を分離。
- 主人公は上下角にも正対するフルビルボードを使用し、見下ろし角による絵の縦つぶれを防ぐ（ADR-006）。正面・背面・左右の画像選択は移動方向とカメラ方向から独立して判定する。
- 3D接地位置とスプライト足元を一致させる。スプライトの向きはワールドの移動方向とカメラ方向から求める。コライダーは見た目に依存させない。
- ピクセルアートの場合は最近傍フィルタ・テクスチャ余白・MipMapの扱いを検証。3D陰影や影との混在は別途視覚テスト。
- 地形との深度テスト/遮蔽と、スプライトの透明部分や重なり順を検証する。
- 主人公歩行画像（ADR-005、2026-10-15）: 144×192px／3列×4行／1枠48×48pxを正式仕様とする。疑似16×16pxの見た目でも原寸を維持し、画像のリサイズ・再描画はしない。行順は下・左・右・上、歩行は各3枚を中央→左→中央→右の4コマ周期（シート列1→0→1→2、0始まり）で再生。停止／再開時は再生スロット0の中央列。現行表示は4方向、斜めは近い方向へ暫定対応する。8方向移動と将来の8方向表示拡張を維持。

## 11. 受け入れ基準 (Given / When / Then)
1. Given 平地, When 8方向入力, Then 斜め方向の最高速度は単軸と同等。
2. Given カメラYawを90°変更, When 前進, Then キャラは画面奥へ移動。
3. Given 地上, When ジャンプ, Then 離陸し着地、2段ジャンプは発生しない。
4. Given 3Dの坂と壁, When 移動, Then 歩行可能な坂のみ登れ、壁を通過しない。
5. Given 有効範囲内の敵と残ストック, When 対象選択, Then 開始位置を保存して踏み込み、1斬撃で1消費する。無効対象は選択・攻撃不可。
6. Given 初期3ストック（仮）, When 受付内で3回攻撃入力, Then 1入力1斬撃で3回消費し、4回目は拒否。予約は最大1、入力停止後は安全に帰還する。
7. Given 接近・攻撃・帰還中, When 敵攻撃命中, Then 被弾判定は有効。防御軽減と単発ステップを検証し、短い回避判定の有無・時間はM08で判断する。
8. Given 同一攻撃ヒットボックス, When 敵に複数フレーム接触, Then 対象への命中は原則1回。
9. Given ゲーム画面, When 敵に接近, Then シーン切替せず戦闘開始。
10. Given 30/60fps描画条件, When FREEでストック回復, Then 同程度の回復時間となり、戦闘各状態では回復停止する。
11. Given 操作不能状態, When 移動攻撃を連打, Then 不正な多段実行や状態固着が発生しない。
12. Given セーブ可能地点, When 保存→終了→再起動, Then 復帰地点と必要フラグが復元される。

### M04遮蔽改善・B方式の正式採用（2026-10-14）
本節はADR-004に基づき、ユーザー実機確認後に正式採用したM04の方式。初回M04補足の距離短縮優先／フェード後続を更新し、B＋影保持を使用する。Aは比較・復帰用として維持。数値は試作値を維持する。

- `camera_settings.gd` の `occlusion_mode`: 0=A（従来SpringArm）、1=B（距離維持＋フェード、初期値）。`resources/camera_settings.tres`はこの初期値を継承する。複雑なUIは追加しない。
- BではSpringArmのネイティブ経路スイープを停止し、Camera3Dをtop_levelにして独立したワールド座標で配置。代わりに `camera_collision.gd` が半径0.25m＋余白0.05mの球で目的位置の重なりと直前位置からのsweepを検査する。視線に壁があるだけでは距離を短縮しない。
- 通常10m。目的位置が不適切なら周囲2mを0.5m刻みで上／左右／前後に探索する。通常の追従・回転に対する補正分は適用／解除とも8m/sを上限とする。候補までの経路も検査。単に位置補間するだけで壁を横断させない。
- 候補へ安全に進めなければ直前の安全位置を保持。初期化／瞬間移動／古い位置自体が塞がれた場合は局所探索、その後上へ2m刻みで最大32mまで探索して即時再配置・補間リセット。通常のスムーズ補正より安全を優先する例外。保持中は注視点が画面中心からずれる場合がある。
- どこにも安全位置がない場合は `safety_failed=true` と警告を出し、camera.cull_mask=0で3D表示を停止し再試行。埋まった視点を正常扱いしない。安全候補が戻れば表示も復帰。任意の完全閉鎖空間での視認性を保証するものではない。Aへの設定切替は可能。
- 視線遮蔽は足元＋Y=0.15／0.9／1.65mに向けた3本のray。各rayでヒットしたbodyを除外しながら最大16体まで検査して複数遮蔽物を収集。毎物理tick更新する。地形mask=1、プレイヤーRID除外。
- `occlusion_fader.gd` は遮蔽物配下のMeshInstance3DごとにBaseMaterial3Dを複製し、個別surface overrideとして使用。元のmaterial_override／surface override／元alpha／影設定を保持。原本の材質や3Dコリジョンは変更しない。
- 不透明度0.3まで0.25秒、遮蔽解除後0.12秒保持して0.25秒で復元。再検出時は現在値から継続する。rigの削除・Aへの切替でも即時復元。削除された遮蔽物は弱参照で除去。
- 複製材質はAlpha blend、透明面はdepthを書かずdepth testは維持。透過中の表示メッシュは影OFFとし、元の形状・材質を持つSHADOWS_ONLY子メッシュで影を維持する（ユーザーの影消失報告を反映）。解除／A切替／rig削除で子を削除し元の影設定へ戻す。元々影OFFなら子は作らない。影用メッシュは遮蔽収集対象外でコリジョンなし。半透明同士の重なりは濃くなる。将来の交差メッシュには描画順の再評価が必要。
- M01では壁／床／坂／高台が別メッシュ。坂と高台の共有材質は複製により干渉しない。壁と床が一つのメッシュならメッシュ全体が薄くなる（面単位の切出しは未実装）。`camera_occlusion_exempt`グループでbodyまたはmesh単位の透過除外が可能だが、遮られた主人公が見える保証はなくなる。
- 対応材質はBaseMaterial3D（StandardMaterial3D／ORMMaterial3D、next_passなし）。ShaderMaterialや追加パスは警告しフェードをスキップする。M01材質は対応済み。新アセットでは適合確認またはA方式を使用する。
- 上記数値は全て試作値。スプライト・移動・ジャンプの値は維持。
- 影補足（2026-10-14）: Bの操作感と影保持はユーザー確認済み、基本方式として採用。影品質は本番の地形・照明に合わせて後続で調整する。M01静的メッシュで検証し、透過で露出する影の縞・ギザつきは残件。スキニング／blend shapeなど変形メッシュの影同期は今回対象外。参考: [GeometryInstance3DのSHADOWS_ONLY](https://docs.godotengine.org/en/4.4/classes/class_geometryinstance3d.html)。

### 主人公の壁際深度補正（2026-10-15、実機確認待ち）
- 実コライダーは半径0.3m・高さ1.8m・中心Y=0.9m。壁四面への実移動で外側停止を確認。物理貫通はなく、絵の幅と上下角による面の傾きが原因。
- pixel_size=0.0375、position=(0,0,0)、offset=(0,23)px、48px原寸、フルビルボード、最近傍、方向選択は維持。画像縮小や物理半径の拡大は行わない。

- 半径・高さは表示スクリプトが実コライダーから読み、個体別ShaderMaterialへ設定する。SpriteFramesのatlas UVを使用し、M05ではフレーム／アニメーション変更時にAtlasTextureの元シートをsamplerへ同期し、歩行・攻撃・ジャンプを切り替える。

- これは2.5D表示用の近似。絵の外縁と身体の奥行き対応が実物の面と異なるため、細い柱・複数透明物・複雑な交差は未検証。Compatibility／Godot 4.7.2で検証し、別レンダラー・別端末・長時間性能は未検証。
- 実装参照: [Godot spatial shader](https://docs.godotengine.org/en/4.6/tutorials/shaders/shader_reference/spatial_shader.html)、[Reverse Z](https://godotengine.org/article/introducing-reverse-z/)。実バイナリの描画検証を優先。
