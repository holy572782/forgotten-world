# 基礎ゲームシステム詳細仕様書 v0.2.0
更新: 2026-10-13 / 対象: Godot 4.x 安定版（導入時に具体的なバージョンを固定）

## 0. ステータス
**採用済みの方針**: Godot / 2Dスプライト+3Dマップ / 斜め見下ろしカメラ・水平回転可能 / 8方向自由移動+ジャンプ / 攻撃ゲージ+回避+コンボ / シームレス戦闘。
**試作の初期値（未承認・調整可能）**: 以下の秒数、速度、倍率、敵ステータス、操作キー、カメラ数値。`GameBalance`等に集約しハードコードを避ける。
**保留**: PC以外の対象機種、スマホ操作、仲間AI、魔法の詳細、最終的なカメラ角度、成長と装備、マルチプレイ、完全シームレス世界、画面解像度、オートターゲットの最終挙動。
本書は「動く試作品を作るための仕様」。世界設定の正本 docs/01_WORLD_BIBLE.md を上書きしない。

## 1. 制作目標と境界
- 最初の10〜15分の縦切りプロトタイプ: 草原(3D)→練習敵→段差とジャンプ→短い洞窟→小ボス→ゴール。
- 先にPCキーボード+ゲームパッドでゲームプレイの品質を検証。モバイル/最適化/広大なマップは後続。
- 3Dは衝突と地形の唯一の正。2Dキャラの見た目だけがSprite3D/AnimatedSprite3D。ワールド座標Yが上、XZが水平面。
- 地形1m=Godotワールド1単位の仮定、物理60 tick/sを初期値とする。フレームレートが変化してもゲーム速度を変えない。

| move_left/right/up/down | A/D/W/S、矢印 | 左スティック | 試作値 |

- キー入力とコントローラー入力は同一アクションAPIを利用する。デッドゾーン初期0.2。
- 斜め入力の速度正規化。左スティックはアナログの強弱を維持。
- UI操作中は攻撃入力しない。再割当可能な設計（画面実装は後続）。

## 3. プレイヤー移動
- `CharacterBody3D` + `CollisionShape3D`（カプセル推奨）、物理処理は `_physics_process(delta)` 内。`move_and_slide()` を使用。
- カメラの前方をXZ水平面に投影して正規化し、入力をカメラ相対ワールド方向へ変換。カメラ回転後もWが画面奥方向を意味する。
- 移動速度 **5.0 m/s**、加速度 **22 m/s²**、減速度 **30 m/s²** は仮。重力 **20 m/s²**、ジャンプ初速 **7.0 m/s**、最大登坂角 **40°**。
- ジャンプは地上または許可されたコヨーテ時間内のみ。空中二段ジャンプは禁止。コヨーテタイム **0.10秒**、ジャンプ入力バッファ **0.12秒** を初期値として試験。空中での方向制御 **地上の70%** は仮。M03では加速度・減速度への係数とし、最高水平速度は地上と共通。ジャンプ押下を1回だけ消費し、長押しによる自動再ジャンプは行わない。
- 自動ステップ登り・移動床・汎用リスポーンは後続チケット。M03ではテストマップ専用の最小落下復帰を実装し、仮の判定高度Y=-10mより下でPlayerSpawnへ戻す。復帰時は速度とジャンプ受付を初期化し、ジャンプの再押下を必要とする。
- 攻撃中は移動速度係数を使い、入力完全停止を標準にしない。被弾中・回避中の優先順位は状態機械で制御。
- 8方向とは**スプライトの向き**の概念。移動方向はアナログで360度、8方向アニメーションに量子化する。

## 4. カメラ
- `Camera3D` を持つリグ (`CameraRig`/`SpringArm3D` 等)。プレイヤー追従、斜め見下ろし、プレイヤーの水平周囲を回転。
- 初期ピッチ **-45°**（Godotノード回転方向は実シーンで確認）、距離 **10m**、回転速度 **100°/s**、追従平滑化 **8.0** は仮。
- 初期版は水平Yaw回転のみ。ズーム、自由ピッチ、ロックオン追従は後続。
- 地形に埋まらないこと。カメラが壁に当たる場合はSpringArm3D等で距離短縮。遮蔽物で主人公が隠れたらフェードまたは輪郭補助（後続）。
- **回転中も入力方向が画面基準で正しく変化**し、キャラクターや地形が不自然に飛ばないこと。

## 5. 2Dスプライトと3D衝突
- プレイヤー本体のコリジョンは3D。表示は `AnimatedSprite3D` を子に置き、アニメーションと見た目を分離。
- 初期版はカメラへ水平面のみ向くYビルボードを基本とし、正面・背面・斜めを含む方向アニメーションを判定。単一仮スプライトで先に操作感を確認してよい。
- 3D接地位置とスプライト足元を一致させる。スプライトの向きはワールドの移動方向とカメラ方向から求める。コライダーは見た目に依存させない。
- ピクセルアートの場合は最近傍フィルタ・テクスチャ余白・MipMapの扱いを検証。3D陰影や影との混在は別途視覚テスト。
- 地形との深度テスト/遮蔽と、スプライトの透明部分や重なり順を検証する。

## 6. 戦闘コア
### 6.1 攻撃ゲージ（0〜100）
- **ゲージは攻撃後に0に戻り、時間経過で100へ回復**。満タンでの攻撃を基本とするが、満タン前でも攻撃を許可。
- 回復時間 **1.2秒**（約83.3ポイント/秒）は仮。ゲージ25/50/75/100での威力倍率を **0.40/0.60/0.80/1.00** と仮設定し、補間式を使う。
- 連打によるダメージ期待値が高くなりすぎないよう、攻撃毎のアニメーション拘束時間、再攻撃可能時刻を明示。ゲージとコンボは別変数。
- 攻撃時に攻撃開始ゲージをスナップショットし、その一撃中は変えない。攻撃アニメイベントでヒットボックスをオン、ヒットウィンドウ終了時にオフ。

### 6.2 コンボ
- 通常攻撃3段を最初の試作とする。攻撃入力は先行入力受付中に最大1回バッファ。
- 各段の初期仕様（秒）: 準備 0.12 / 判定 0.10 / 後隙 0.20。次段受付ウィンドウ 0.15〜0.38、途切れ後 **0.65秒** で1段目へ戻る。全て仮。
- 2段目以降もゲージを適用するかは検証事項。**v0.2試作品ではコンボ継続時のゲージを別扱い（連続技中は段間で回復、各段で消費）**とし、異なる設計を比較可能にする。
- ヒットボックスは攻撃者ごとに対象IDを記録し、同じ振りで同じ敵への多重ヒットを防ぐ。

### 6.3 回避
- 回避距離 **3m**、所要時間 **0.35秒**、無敵時間 **0.12〜0.28秒**（移動開始をt=0）、クールダウン **0.25秒** は仮。
- 回避方向は移動入力があればその方向、なければキャラの向き。無敵は敵攻撃ヒット判定のみ、落下や地形衝突は対象外。
- 当面スタミナは導入せず、クールダウンで制御（スタミナ制は保留）。

### 6.4 体力・ダメージ・敵
- 初期サンプル: 主人公HP100、練習敵HP40/攻撃10、小ボスHP250/攻撃15（すべて仮）。
- `HealthComponent` が `damage(amount, source)`/死亡通知を所有。攻撃側はヒット判定とダメージイベントを所有。
- 敵状態: Idle→Chase→Windup→Attack→Recovery→Chase、距離でLeash/Return。ボスは攻撃予兆を最低0.5秒表示。
- プレイヤーの死亡時はリスポーン。アイテム・経験値・ドロップは後続。
- ヒット停止、ノックバック、画面振動、SEは段階導入。無敵中は被ダメージとヒット反応を抑止する。

### 6.5 状態の優先順位
- 優先: Dead > Stunned > Dodge > Attack > Jump/Fall > Move/Idle。**Jump中のAttack可否、Attack中のDodgeキャンセル可能時点は調整フラグ**で決定する。
- 状態遷移条件をコードから確認可能にする（スパゲティなif連鎖を避ける）。イベント重複による多重攻撃は禁止。

## 7. HUD / カメラ / 操作フィードバック
- HUD: HPバー、攻撃ゲージ0〜100、コンボ段数（開発デバッグ表示）。
- ゲージの色だけに頼らず数値や形状でも認識可能にする。ゲームパッドとキーボードで同一情報を表示。
- デバッグHUD: FPS、状態名、ゲージ、現在速度、接地フラグ、入力方向、カメラyaw、直近ヒット数。

## 8. 探索とインタラクト（試作品）
- 3D地面/坂/段差/ジャンプで到達できる高台、洞窟入口、トリガーゾーン、宝箱のプロキシを設置。
- `Interactable`のインターフェースを定義。会話や宝箱のコンテンツは後から差し替え可能にする。
- 世界観で提案された「残響」は別機能フラグ。**基礎アクションの受入完了後**に「短時間出現する橋」の一機能として試す。仕様を物語都合で固定しない。

## 9. 永続化/データ
- 最初は`ConfigFile`かJSON等の軽い保存形式を選定し、バージョン番号を持たせる。保存内容: 最後の復帰地点、HP、簡単なフラグ、設定。
- 戦闘中セーブは試作では不可。破損やバージョン不一致では安全な初期化とログ出力。
- 敵/武器/ヒットボックス/モーション数値は可能な限り`Resource`でデータ駆動化。

## 10. 非機能・品質基準（目標値）
- PCの指定検証機で60fpsを目標。現時点で検証機未指定のため**性能保証ではない**。
- 60Hzで同一操作の挙動に大きなばらつきがないこと。30fps描画時にも物理速度とゲージ速度が概ね一定。
- シーンの差替えで無関係の仕様が壊れない。外部アセットなしでもプレースホルダーで起動可能にする。
- 主要ロジックの単体/ヘッドレステスト+手動操作テストを両方記録。

## 11. 受け入れ基準 (Given / When / Then)
1. Given 平地, When 8方向入力, Then 斜め方向の最高速度は単軸と同等。
2. Given カメラYawを90°変更, When 前進, Then キャラは画面奥へ移動。
3. Given 地上, When ジャンプ, Then 離陸し着地、2段ジャンプは発生しない。
4. Given 3Dの坂と壁, When 移動, Then 歩行可能な坂のみ登れ、壁を通過しない。
5. Given 攻撃ゲージ100と25, When 同条件で敵を攻撃, Then 100の方が高ダメージ。
6. Given 連続入力, When コンボ受付時間内, Then 最大3段まで遷移し、時間超過で1段目へ戻る。
7. Given 回避無敵時間, When 敵攻撃判定, Then HPは減らず、無敵時間外は減る。
8. Given 同一攻撃ヒットボックス, When 敵に複数フレーム接触, Then 対象への命中は原則1回。
9. Given ゲーム画面, When 敵に接近, Then シーン切替せず戦闘開始。
10. Given 30/60fps描画条件, When 一定時間ゲージ回復, Then 同程度の回復時間となる。
11. Given 操作不能状態, When 移動攻撃を連打, Then 不正な多段実行や状態固着が発生しない。
12. Given セーブ可能地点, When 保存→終了→再起動, Then 復帰地点と必要フラグが復元される。
