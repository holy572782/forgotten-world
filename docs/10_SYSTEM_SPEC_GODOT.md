# 基礎ゲームシステム詳細仕様書 v0.3.0
更新: 2026-10-17 / 対象: Godot 4.x 安定版（導入時に具体的なバージョンを固定）

## 0. ステータス
**採用済みの方針**: Godot / 2Dスプライト+3Dマップ / 斜め見下ろしカメラ・水平回転可能 / 8方向自由移動+ジャンプ / 選択式踏み込み・攻撃ストック・防御／方向ステップ / シームレス戦闘。
**試作の初期値（未承認・調整可能）**: 以下の秒数、速度、倍率、敵ステータス、操作キー、カメラ数値。`GameBalance`等に集約しハードコードを避ける。
**保留**: PC以外の対象機種、スマホ操作、仲間AI、魔法の詳細、最終的なカメラ角度、成長と装備、マルチプレイ、完全シームレス世界、画面解像度、オートターゲットの最終挙動。
本書は「動く試作品を作るための仕様」。世界設定の正本 docs/01_WORLD_BIBLE.md を上書きしない。

## 1. 制作目標と境界
- 最初の10〜15分の縦切りプロトタイプ: 草原(3D)→練習敵→段差とジャンプ→短い洞窟→小ボス→ゴール。
- 先にPCキーボード+ゲームパッドでゲームプレイの品質を検証。モバイル/最適化/広大なマップは後続。
- 3Dは衝突と地形の唯一の正。2Dキャラの見た目だけがSprite3D/AnimatedSprite3D。ワールド座標Yが上、XZが水平面。
- 地形1m=Godotワールド1単位の仮定、物理60 tick/sを初期値とする。フレームレートが変化してもゲーム速度を変えない。

## 3. プレイヤー移動
- `CharacterBody3D` + `CollisionShape3D`（カプセル推奨）、物理処理は `_physics_process(delta)` 内。`move_and_slide()` を使用。
- カメラの前方をXZ水平面に投影して正規化し、入力をカメラ相対ワールド方向へ変換。カメラ回転後もWが画面奥方向を意味する。
- 移動速度 **5.0 m/s**、加速度 **22 m/s²**、減速度 **30 m/s²** は仮。重力 **20 m/s²**、ジャンプ初速 **7.0 m/s**、最大登坂角 **40°**。
- ジャンプは地上または許可されたコヨーテ時間内のみ。空中二段ジャンプは禁止。コヨーテタイム **0.10秒**、ジャンプ入力バッファ **0.12秒** を初期値として試験。空中での方向制御 **地上の70%** は仮。M03では加速度・減速度への係数とし、最高水平速度は地上と共通。ジャンプ押下を1回だけ消費し、長押しによる自動再ジャンプは行わない。
- 自動ステップ登り・移動床・汎用リスポーンは後続チケット。M03ではテストマップ専用の最小落下復帰を実装し、仮の判定高度Y=-10mより下でPlayerSpawnへ戻す。復帰時は速度とジャンプ受付を初期化し、ジャンプの再押下を必要とする。
- FREEでは既存移動・ジャンプを維持。新戦闘の接近・攻撃中の方向入力は対象を向いた単発ステップ要求としてM08で扱う。通常移動との競合・空中からの開始条件・割込み時点は試作で検証する。
- 8方向とは**スプライトの向き**の概念。移動方向はアナログで360度、8方向アニメーションに量子化する。

## 4. カメラ
- `Camera3D` を持つリグ (`CameraRig`/`SpringArm3D` 等)。プレイヤー追従、斜め見下ろし、プレイヤーの水平周囲を回転。
- 初期ピッチ **-45°**（Godotノード回転方向は実シーンで確認）、距離 **10m**、回転速度 **100°/s**、追従平滑化 **8.0** は仮。
- 初期版は水平Yaw回転のみ。ズーム、自由ピッチ、ロックオン追従は後続。
- 地形に埋まらないこと。ADR-004により、B「距離維持＋遮蔽物フェード」を正式採用し、影保持を継続する。カメラ本体の衝突は独立して補正する。従来のSpringArm距離短縮方式Aは比較・復帰用として保持。輪郭補助は後続。
- 採用根拠（2026-10-14、ユーザー実機操作）: 急激なズームの解消、壁の正常な半透明化、壁背後のキャラクターの視認性と快適な操作感を確認。方式の正式採用であり、試作数値の固定や未検証項目の合格を意味しない。
- **回転中も入力方向が画面基準で正しく変化**し、キャラクターや地形が不自然に飛ばないこと。

## 5. 2Dスプライトと3D衝突
- プレイヤー本体のコリジョンは3D。表示は `AnimatedSprite3D` を子に置き、アニメーションと見た目を分離。
- 主人公は上下角にも正対するフルビルボードを使用し、見下ろし角による絵の縦つぶれを防ぐ（ADR-006）。正面・背面・左右の画像選択は移動方向とカメラ方向から独立して判定する。
- 3D接地位置とスプライト足元を一致させる。スプライトの向きはワールドの移動方向とカメラ方向から求める。コライダーは見た目に依存させない。
- ピクセルアートの場合は最近傍フィルタ・テクスチャ余白・MipMapの扱いを検証。3D陰影や影との混在は別途視覚テスト。
- 地形との深度テスト/遮蔽と、スプライトの透明部分や重なり順を検証する。
- 主人公歩行画像（ADR-005、2026-10-15）: 144×192px／3列×4行／1枠48×48pxを正式仕様とする。疑似16×16pxの見た目でも原寸を維持し、画像のリサイズ・再描画はしない。行順は下・左・右・上、歩行は各3枚を中央→左→中央→右の4コマ周期（シート列1→0→1→2、0始まり）で再生。停止／再開時は再生スロット0の中央列。現行表示は4方向、斜めは近い方向へ暫定対応する。8方向移動と将来の8方向表示拡張を維持。
- 表示専用player_spriteが既存direction_sectorを4分割で再利用し、カメラ回転中／停止中もワールド方向から表示を更新。4方向の同距離境界はroundiで決める。水平の実移動速度で再生し、停止／壁で移動できないときは中央フレーム。M05では専用ジャンプ画像の列0／1／2を上昇／落下／着地に仮割当。表示状態の優先はAttack > Jump/Fall > Land > Walk/Idle。現行M05プレビューでは攻撃中も物理移動は制限しない。新戦闘の状態制御は第6節へ移行予定。
- 表示の試作値: 6fps、pixel_size=0.0375、表示ノード位置はボディ原点、offset=(0,23)px（画像内の足元下端47px、中心24px）。可視足元を回転の基準にし、上下角が変わっても接地基準を維持する。コライダー・移動速度・ジャンプ値は不変。ロスレス／MipMapなし／最近傍／48px領域参照で元画像ピクセルを維持。

### 6.1 攻撃ストックへの移行
- M06で0〜100の攻撃ゲージを攻撃回数ストックへ変更。初期／最大3、1攻撃受理で1消費、0では新規攻撃不可（数値は仮）。
- 帰還後のFREEだけで1.5秒ごとに1回復（仮）。接近・攻撃・防御・ステップ・帰還中は回復停止。最大数・回復間隔をResourceへ集約する。
- AttackStockComponentの新設を推奨。値・消費・回復・通知を所有し、HUDは表示のみ。予約と実行で二重消費しない。キャンセル時の消費／返却の詳細は実装Issueで仮方針を記録する。
- 旧仕様の開始ゲージ値による威力倍率（25/50/75/100に0.40/0.60/0.80/1.00）は新戦闘では採用しない。M05は開始値保存までの実装で、敵へのダメージ計算は未実装。基本威力・段ごとの倍率は未決定であり、残ストック数を威力へ自動転用しない。

### 6.2 選択・踏み込み・単発攻撃・予約
- 水平円形の武器別開始範囲（半径5mは例）を設定。生存・選択可能かつ距離／高低差／壁／経路／着地条件を満たす敵にだけマークを表示。範囲円は敵検出時等に控えめに表示する試作方針。
- 右クリックで最前面の有効Targetableを選択。敵1体1ターゲットとし、部位選択は後続。UI入力と競合させない。
- 開始位置return_anchorを3D保存し、視認可能な速度で攻撃位置へ踏み込む。Spaceジャンプと別状態で、二段ジャンプにしない。
- 踏み込みは既存assets/sprites/player/player_jump.png、斬撃はplayer_attack.pngを使用。48px・方向順・足元・フルビルボード・null atlas修正を維持。原本とゲーム用PNGは変更しない。
- 一入力＝一斬撃＝一ストック消費。見た目の命中フレームと判定を同期し、同じ対象は一斬撃一ヒット。M07で最大1個の予約と最大3段（仮）を導入。旧コンボのゲージ段間回復・0.65秒リセットは新仕様に引き継がない。

### 6.3 防御・方向ステップ・自動帰還
- M08で接近／攻撃中の方向キー押下を対象向きの単発ステップにする。長押しで連続しない。防御入力で攻撃を中断し、軽減・硬直を試作値で検証する。
- 接近・攻撃・帰還中も被弾判定は有効。旧回避の距離3m／時間0.35秒／無敵0.12〜0.28秒／クールダウン0.25秒は旧案として扱い、自動適用しない。短い回避判定の有無と時間、割込みフレームはM08の操作検証で判断する。
- 最終攻撃の入力受付終了後、追加入力なし約0.5秒（仮）で帰還。防御／ステップ動作の終了と追撃受付を待つ。帰還中の防御・回避割込みはM08で試作検証する。
- 開始位置が塞がれたら安全な最寄り地点へ帰還し差をデバッグ表示。壁抜け・地形外への落下を禁止。対象死亡／喪失／範囲外化は接近を中止して安全な位置へ戻す。

### 6.4 体力・ダメージ・敵
- 主人公HP100、練習敵HP40／攻撃10、小ボスHP250／攻撃15は引き続き仮値。HealthComponentがdamage(amount, source)と死亡通知を所有する。
- M09で敵の索敵範囲・攻撃開始距離・実際の攻撃判定範囲を分離。Idle→Chase→Windup→Attack→Recovery→Chase、距離でLeash/Return。ボス予兆0.5秒以上は仮値。
- 接近・攻撃・帰還中にも敵は反撃。ガード中も被弾判定を行い、帰還中の操作不能による理不尽な被弾、予告と実際の命中位置の一致を検証する。
- 死亡後リスポーンは後続実装。ヒット停止・ノックバック・画面振動・SEは段階導入、アイテム等は後続。

### 6.5 状態と優先順位
- FREE → TARGETED → APPROACH → ATTACK → [追加ATTACK / GUARD / STEP / RETURN] → FREE。
- DEAD／STUNNEDを優先し、攻撃・帰還・予約を中断。通常移動／ジャンプと戦闘状態を分離し、重複イベント・状態固着を防ぐ。
- 中断可能フレーム、防御／ステップの競合優先、空中での開始条件は未決定。M05空中攻撃プレビューの許可を新戦闘の確定仕様としない。

## 10. 非機能・品質基準（目標値）
- PCの指定検証機で60fpsを目標。現時点で検証機未指定のため**性能保証ではない**。
- 60Hzで同一操作の挙動に大きなばらつきがないこと。30fps描画時にも物理速度・踏み込み／帰還時間・ストック回復が概ね一定。
- シーンの差替えで無関係の仕様が壊れない。外部アセットなしでもプレースホルダーで起動可能にする。
- 主要ロジックの単体/ヘッドレステスト+手動操作テストを両方記録。

## 11. 受け入れ基準 (Given / When / Then)
1. Given 平地, When 8方向入力, Then 斜め方向の最高速度は単軸と同等。
2. Given カメラYawを90°変更, When 前進, Then キャラは画面奥へ移動。
3. Given 地上, When ジャンプ, Then 離陸し着地、2段ジャンプは発生しない。
4. Given 3Dの坂と壁, When 移動, Then 歩行可能な坂のみ登れ、壁を通過しない。
5. Given 有効範囲内の敵と残ストック, When 対象選択, Then 開始位置を保存して踏み込み、1斬撃で1消費する。無効対象は選択・攻撃不可。
6. Given 初期3ストック（仮）, When 受付内で3回攻撃入力, Then 1入力1斬撃で3回消費し、4回目は拒否。予約は最大1、入力停止後は安全に帰還する。
7. Given 接近・攻撃・帰還中, When 敵攻撃命中, Then 被弾判定は有効。防御軽減と単発ステップを検証し、短い回避判定の有無・時間はM08で判断する。
8. Given 同一攻撃ヒットボックス, When 敵に複数フレーム接触, Then 対象への命中は原則1回。
9. Given ゲーム画面, When 敵に接近, Then シーン切替せず戦闘開始。
10. Given 30/60fps描画条件, When FREEでストック回復, Then 同程度の回復時間となり、戦闘各状態では回復停止する。
11. Given 操作不能状態, When 移動攻撃を連打, Then 不正な多段実行や状態固着が発生しない。
12. Given セーブ可能地点, When 保存→終了→再起動, Then 復帰地点と必要フラグが復元される。

### M04遮蔽改善・B方式の正式採用（2026-10-14）
本節はADR-004に基づき、ユーザー実機確認後に正式採用したM04の方式。初回M04補足の距離短縮優先／フェード後続を更新し、B＋影保持を使用する。Aは比較・復帰用として維持。数値は試作値を維持する。

- `camera_settings.gd` の `occlusion_mode`: 0=A（従来SpringArm）、1=B（距離維持＋フェード、初期値）。`resources/camera_settings.tres`はこの初期値を継承する。複雑なUIは追加しない。
- BではSpringArmのネイティブ経路スイープを停止し、Camera3Dをtop_levelにして独立したワールド座標で配置。代わりに `camera_collision.gd` が半径0.25m＋余白0.05mの球で目的位置の重なりと直前位置からのsweepを検査する。視線に壁があるだけでは距離を短縮しない。
- 通常10m。目的位置が不適切なら周囲2mを0.5m刻みで上／左右／前後に探索する。通常の追従・回転に対する補正分は適用／解除とも8m/sを上限とする。候補までの経路も検査。単に位置補間するだけで壁を横断させない。
- 候補へ安全に進めなければ直前の安全位置を保持。初期化／瞬間移動／古い位置自体が塞がれた場合は局所探索、その後上へ2m刻みで最大32mまで探索して即時再配置・補間リセット。通常のスムーズ補正より安全を優先する例外。保持中は注視点が画面中心からずれる場合がある。
- どこにも安全位置がない場合は `safety_failed=true` と警告を出し、camera.cull_mask=0で3D表示を停止し再試行。埋まった視点を正常扱いしない。安全候補が戻れば表示も復帰。任意の完全閉鎖空間での視認性を保証するものではない。Aへの設定切替は可能。
- 視線遮蔽は足元＋Y=0.15／0.9／1.65mに向けた3本のray。各rayでヒットしたbodyを除外しながら最大16体まで検査して複数遮蔽物を収集。毎物理tick更新する。地形mask=1、プレイヤーRID除外。
- `occlusion_fader.gd` は遮蔽物配下のMeshInstance3DごとにBaseMaterial3Dを複製し、個別surface overrideとして使用。元のmaterial_override／surface override／元alpha／影設定を保持。原本の材質や3Dコリジョンは変更しない。
- 不透明度0.3まで0.25秒、遮蔽解除後0.12秒保持して0.25秒で復元。再検出時は現在値から継続する。rigの削除・Aへの切替でも即時復元。削除された遮蔽物は弱参照で除去。
- 複製材質はAlpha blend、透明面はdepthを書かずdepth testは維持。透過中の表示メッシュは影OFFとし、元の形状・材質を持つSHADOWS_ONLY子メッシュで影を維持する（ユーザーの影消失報告を反映）。解除／A切替／rig削除で子を削除し元の影設定へ戻す。元々影OFFなら子は作らない。影用メッシュは遮蔽収集対象外でコリジョンなし。半透明同士の重なりは濃くなる。将来の交差メッシュには描画順の再評価が必要。
- M01では壁／床／坂／高台が別メッシュ。坂と高台の共有材質は複製により干渉しない。壁と床が一つのメッシュならメッシュ全体が薄くなる（面単位の切出しは未実装）。`camera_occlusion_exempt`グループでbodyまたはmesh単位の透過除外が可能だが、遮られた主人公が見える保証はなくなる。
- 対応材質はBaseMaterial3D（StandardMaterial3D／ORMMaterial3D、next_passなし）。ShaderMaterialや追加パスは警告しフェードをスキップする。M01材質は対応済み。新アセットでは適合確認またはA方式を使用する。
- 上記数値は全て試作値。スプライト・移動・ジャンプの値は維持。
- 影補足（2026-10-14）: Bの操作感と影保持はユーザー確認済み、基本方式として採用。影品質は本番の地形・照明に合わせて後続で調整する。M01静的メッシュで検証し、透過で露出する影の縞・ギザつきは残件。スキニング／blend shapeなど変形メッシュの影同期は今回対象外。参考: [GeometryInstance3DのSHADOWS_ONLY](https://docs.godotengine.org/en/4.4/classes/class_geometryinstance3d.html)。

### 主人公の壁際深度補正（2026-10-15、実機確認待ち）
- 実コライダーは半径0.3m・高さ1.8m・中心Y=0.9m。壁四面への実移動で外側停止を確認。物理貫通はなく、絵の幅と上下角による面の傾きが原因。
- pixel_size=0.0375、position=(0,0,0)、offset=(0,23)px、48px原寸、フルビルボード、最近傍、方向選択は維持。画像縮小や物理半径の拡大は行わない。
- player_depth.gdshaderで画面上の絵の形を維持し、各画素に対応する直立カプセル内の代理位置で不透明地形の深度を照合。身体が遮られている画素はdiscardし、可視な身体の絵の張り出しだけを深度補正する。無条件の最前面表示／深度テスト全面無効化はしない。
- 半径・高さは表示スクリプトが実コライダーから読み、個体別ShaderMaterialへ設定する。SpriteFramesのatlas UVを使用し、M05ではフレーム／アニメーション変更時にAtlasTextureの元シートをsamplerへ同期し、歩行・攻撃・ジャンプを切り替える。
- シェーダーの深度参照と影描画を分離し、同じSpriteFrames・フレームのShadow子ノードをSHADOWS_ONLYで同期。地形のM04影保持・フェード・検出rayは変更しない。
- これは2.5D表示用の近似。絵の外縁と身体の奥行き対応が実物の面と異なるため、細い柱・複数透明物・複雑な交差は未検証。Compatibility／Godot 4.7.2で検証し、別レンダラー・別端末・長時間性能は未検証。
- 実装参照: [Godot spatial shader](https://docs.godotengine.org/en/4.6/tutorials/shaders/shader_reference/spatial_shader.html)、[Reverse Z](https://godotengine.org/article/introducing-reverse-z/)。実バイナリの描画検証を優先。


### M05実装補足（2026-10-15、試作値）
以下は完了済みM05の現行実装記録。ゲージ・AttackPreview・HUDは今回保持し、M06で第6節へ移行する。M05で敵へのダメージ計算を実装したという意味ではない。
- HealthComponentはHPの所有者。最大／初期100、下限0。damage(amount, source)／heal(amount)は正の有限値のみ受理し、上下限へ制限。実値変化時にhp_changed(current, maximum)、正から0への遷移時にdepleted(source)を通知。死亡演出・敵・復帰処理は接続しない。
- AttackGaugeComponentはfloatの0〜100を所有。初期100、consume()は開始値を返して0へ戻す。通常_process(delta)で最大値／1.2秒（約83.333/秒）を回復し、変更時にgauge_changed(current, maximum)。負値・非有限deltaは無視。描画フレームの粒度で満タン表示に最大約1フレームの差がある。
- 初期値はscripts/combat/combat_balance.gd、共有の設定Resourceはresources/combat_balance.tres。実行時のHP／ゲージ値は各Componentに保持し、Resource共有で他の個体へ伝播しない。設定は起動前に編集する。
- M05のAttackPreviewは表示のattack_startedを受けてゲージを消費し、開始値を保存するだけの接続。M06では正式な攻撃受理処理へ移す。100未満でも攻撃可能。再生中の入力は予約せず無視、消費は再生開始1回につき1回。敵のヒット判定・ダメージ・コンボ・回避なし。
- 表示優先はAttack > Jump/Fall > Land > Walk/Idle。攻撃は3コマ8fps（仮）、カメラ回転時の方向変更でも再生位相を保つ。移動を制限せず、攻撃開始時のワールド向きを表示用に保持。空中攻撃は試作で許可し、終了時にまだ空中ならJump/Fallへ戻る。空中攻撃の正式ルールはM06以降。
- ジャンプは3コマを登録し、列0=上昇、列1=落下、列2=着地0.12秒として再利用。コマの作者意図は未確認で、この対応は試作。歩行のみ4コマ周期を維持。48px、最近傍、RGBA、足元、フルビルボード、M04 B・影保持を維持。
- HUDはCanvasLayer＋Control。HP／ゲージのバー・数値はシグナルで同期し、FPS／状態／接地／速度／Yaw／ゲージ詳細は読み取り表示のみ。Mainで従来の案内を非表示にし、test_arena単体F6の案内は維持。HPを減らすユーザー操作は追加しない。
