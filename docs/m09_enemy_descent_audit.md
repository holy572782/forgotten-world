# M09完了後：階段の下り追跡修正（2026-11-02、ADR-056）

M09基本戦闘完了／M10別指示待ちを維持する。今回の下り操作感と実ユーザー環境の長時間性能はF5確認待ち。開始時HEAD `71ba493`、作業ツリーはクリーン。位置確定型AIの既存差分はユーザーがコミット済みだった。

## 原因の切り分け

実mainの回転済みTestArenaを使い、雑兵・魔導士の正式Resource（剣の開始5m／魔法6m、照準ratio 0.4／0.5）を維持して比較した。移動単体はAIを止めて同じEnemyWalkを駆動し、射程を0.2mへ変更しない。

- **主因は移動の事前判定**。`EnemyWalk._work_can_reach()`が、上段から下段の床へ斜めの直線を掃引していた。カプセル後方がまだ上段に支持される位置では階段の角と衝突する。その失敗を上り専用の代替処理では解決できず、無制限追跡の直接経路／A*の辺を拒否していた。
- 修正前、両敵は実階段上端の世界座標約`(1.9334, 0.995, 5)`で8秒間停止し、`NO_SAFE_LOCAL_ROUTE`。一方、同じ歩行処理を直接駆動すると下端へ到達した。FALL／STRANDEDや床snap不足による一律の停止ではなかった。
- **攻撃AIにも別の停止条件**があった。魔導士は既存の+0.8mの視線と6mの距離だけで停止／詠唱を開始できた。実際の+0.9mの発射線やmuzzle球が塞がる場合は発射が失敗しても接近を再開できなかった。
- **射程境界では実際の空中停止も再現**。経路検査だけを直した後の追加試験でも、通常歩行の落下がWALKのままでbusyにならず、降下中に射程へ入ると攻撃判断／詠唱／回復へ移って重力更新が止まった。1m段差から正式な6m射程へ入る3配置で、魔導士はY=0.794119／0.710786／0.546897m、native接地=falseのまま1.5秒後も同じ位置にいた。FALL／STRANDEDに移ることが原因ではなく、通常降下を移動の継続状態にしていなかったことが原因。
- 上段から安全に攻撃できる魔導士が下りないことは正常。修正前にも、無制限OFFでは中段の足場まで降りて魔法を使った。上下差を無視して全敵を下段へ強制移動させる修正はしない。照準固定後の追尾禁止やRECOVERY時間も変更しない。

## 修正方法

`enemy_walk.gd`の経路検査だけに下り接触の評価を追加。上り／下りの許容量をそれぞれ`maximum_step_up`／`maximum_step_down`で確認し、段差の縁では上段の高さから足元周囲の実支持を検査する。

下降する候補は現在の高さで水平に全身を掃引した後、下段へ全身を下向きに掃引する。上段の縁に接触したら、その**実際の接触位置まで**で止め、次のサンプルをそこから続ける。接触を貫通して下段の高さへ置くことはしない。水平な壁接触は拒否する。下段の支持／最大下降高さ、従来の床・壁・天井・身体衝突の検査は維持。

実移動は従来の`move_and_slide()`／重力／床判定を利用する。同じEnemyWalkのMotion末尾へDESCENDを追加し、通常歩行が床を離れて下降したら、攻撃判断へ移る前に着地までこの所有者で更新を続ける。水平移動と重力を継続し、足場／home範囲を毎tick確認、壁は実衝突で止まる。床の消失が続けば既存の2秒安全期限でSTRANDEDへ移る。別の移動コンポーネント／ジャンプ軌道や瞬間的な位置変更は追加しない。

低段差／0.5〜1mの下りでも上向きにジャンプせず、nativeの実接地後に通常歩行／攻撃へ戻る。下降着地ではジャンプ回数／ジャンプクールダウンを増やさない。床snapは0.12m、最大下りは1.05m、斜面上限45度の既定値を変更しない。上りジャンプは既存の別経路。カプセルの丸い底が階段の角に実際に接地している場合は、その接地を尊重し、中心の床rayだけで空中と誤判定しない。

魔導士の停止位置は既存の攻撃候補キャッシュを共用して、実発射線とmuzzle球の安全性も確認する。塞がっていれば安全歩行を続け、直接移動不能なら無制限モードでは既存の局所迂回を使う。無理な経路は許可せず停止する。詠唱入口と実発射では新たに検査する。確定後の発射検査は固定地点を使い、現在の主人公へ再照準しない。
