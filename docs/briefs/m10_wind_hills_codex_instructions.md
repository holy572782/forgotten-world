## 1. この依頼で行うこと

添付の主人公入り水彩スケッチを参考に、本番へ育てられる小規模な3D探索フィールドを制作してください。**最初の実装は本書の工程A「全体地形・歩行・構図確認」まで**です。入口から頂上遺跡、左の見晴らし台、右の橋までの地形を一通り配置し、既存の主人公で歩ける状態にします。

## 4. エリア全体と仮寸法

### 今回歩ける範囲

入口から頂上までの主経路、左側の寄り道と合流路、右側の川へ下りる道と石橋・対岸の小さな広場を作ります。遠方の山岳・巨大な橋状遺構・白化した土地は遠景です。見えている全世界を同時に歩行可能にしません。

| 要素 | 初期寸法の目安 |
|---|---|
| 主エリアの外接範囲 | 東西約260m×南北約300m。全面を平地や通路で埋めない |
| 入口〜頂上の比高 | 約44m。谷底は入口より約10〜12m低い |
| 入口〜頂上の実経路長 | 曲がり・緩斜面を含め約300〜380mを狙い、実際に計測 |
| 主街道の有効歩行幅 | 5〜7m。草の余白を含む見た目は7〜10m程度 |
| 寄り道の有効歩行幅 | 3〜4m。危険な縁沿いは3.5m以上を初期目安にする |
| 将来の戦闘用広場 | 直径または短辺20〜24m程度。初回は敵なし |
| 入口の門 | 開口幅4〜4.5m、高さ5.5〜6m。門本体高さ8〜9m、両脇の壁を含む幅11〜13m |
| 石段の通路 | 幅5〜6m、短い階段列の間に踊り場 |
| 左の見晴らし台 | 有効範囲14〜18m程度 |

寸法表と下記座標が競合する場合は、接地・勾配・有効道幅・場所のつながりを優先し、変更後の実値と理由を記録してください。寸法を満たすために移動性能を変更しません。

現行最高速度5m/sなら、300〜380mの距離を最高速度だけで進む換算は約60〜76秒です。加減速や寄り道を含む実時間は別に計測します。初回の敵なし地形に、10〜15分の長さを無理に要求しないこと。探索時間は道幅・曲がり・寄り道の手応えで判断します。

## 5. 配置の目安と場所のつながり

ワールドYが上。入口の石門中央の足元を(0,0,0)、画像の奥を-Z、右を+Xとします。これはレイアウト用の仮座標であり、既存カメラYawと混同しないこと。

| ID / 場所 | 目安座標 (X,Y,Z)m | 内容 |
|---|---|---|
| A / 開始地点 | (0,0,12) | 門の手前。安全な平地で移動とカメラを試せる |
| B / 入口の門 | (0,0,0) | 主人公と建築物の縮尺を最初に確認する場所 |
| C / 街道の草地 | (0,2,-45) | 石畳・草地・低い壁。将来の最初の戦闘候補 |
| D / 分岐 | (-10,8,-80) | 主街道と左の見晴らし台への道が分かれる |
| E / 中腹の踊り場 | (15,18,-125) | 坂と階段の切替。十分な平坦面を置く |
| F / 上部段丘 | (0,30,-175) | 高低差が増え、背後の景色を見返せる |
| G / 頂上遺跡 | (30,44,-230) | M10の到達地点。次の土地を示す遠景が見える |
| H / 左の見晴らし台 | (-90,16,-100) | 画像左の樹木と小遺構。入口と主経路を見返す |
| I / 川沿いの石橋 | (95,-8,-65) | 街道の草地から下り、谷と川の高さを体験する |
| J / 対岸の小広場 | (115,-7,-90) | 橋を渡った先。将来の拡張方向を示す終端 |

主経路：A→B→C→D→E→F→G。

左の寄り道：D→H。Hから(-65,21,-130)付近の裏道を回り、Eへ合流できるループにする。高低差を一直線の崖登りでつながず、横へ回る緩い斜面や踊り場を挟む。帰り道があることを地形から読めるようにする。

右の寄り道：C→I→J。川側へ下る道を用意し、橋から水面までの距離を確保する。泳ぎ・水中移動は追加しない。川は水面表現と川床を持つ簡単な地形とし、非対応の深水部へ入れる場合は安全な復帰領域を設ける。

石畳を全区間に敷き詰める必要はない。途切れた石畳・草の踏み跡・石段で同じ道が続く印象を作る。主経路はジャンプ必須にせず、既存操作で歩いて往復できる構成にする。小さな跳び越しは、後の任意寄り道として追加可能な余地を残す。

## 6. 移動・階段・衝突の条件

- 主経路の斜面は概ね12〜25度、短い急斜面でも30度程度を目安にし、現行の最大登坂角40度へ常時張り付かせない。
- 現行主人公に汎用の自動段差登りがあると決めつけない。階段の見た目を置くだけで通常歩行できると扱わない。
- 工程Aの階段は、見た目の段高0.12〜0.16m・踏面0.4〜0.5m程度の意匠と、歩行可能な連続斜面Colliderを組み合わせる方式を候補とする。階段本体と斜路のColliderを重複させない。
- 階段用斜路と平地をなめらかにつなぎ、継ぎ目・段の鼻先で足元が大きく浮く／埋まる場合は、段意匠や斜路を調整する。主人公に新しい段差登りロジックを追加して解決しない。
- 道の途中に意図しない数十cmの垂直な切れ目、極薄の足場、衝突だけの突起を作らない。門のアーチは開口を保ち、単一のBoxで入口全体を塞がない。
- 地形の衝突レイヤーは既存方針（地形layer 1）に合わせる。崖・壁・床・頭上の衝突を省略して見た目だけ通れる状態にしない。
- プレイヤーが立つ地形は傾斜とColliderを一致させる。岩の装飾と歩行床の境界が見た目で区別できること。
- 落下・川・外周から復帰できるよう、エリアごとの復帰領域を設ける。大きな比高のあるマップへ既存mainのY=-10だけをそのまま流用しない。
- 初回の復帰先は入口の安全地点。位置は新マップの管理スクリプトが決め、既存 `Player.reset_motion(at)` と `CameraRig.snap_to_target()` を再利用する。このreset_motionは現行実装で戦闘cancelも呼ぶため、直接positionだけを書き換えて予約・カメラ固定を残さない。
- 永続セーブ・正式な死亡／チェックポイントシステムは追加しない。初回は既存シーンを再実行して再開できればよい。敵を置く後工程でHP0時の再挑戦を明確にする。

## 7. カメラと遠景の見せ方

画像は全体を見渡すコンセプト構図であり、通常プレイ画面そのものではありません。次の二つを分けます。

1. **通常プレイ**：既存CameraRigの追従、Q/E回転、M04方式B・影保持、攻撃中の基準固定と帰還後の追従復帰を継続。まず既存距離10m／ピッチ-45度で操作・安全性を確認する。
2. **全景確認**：画像と地形を比較するため、エディター用または独立したプレビューシーンに全体用カメラを置く。通常プレイの入力や当たり判定をこのカメラへ依存させない。

既存の-45度カメラでは、遠方の高い遺跡や水平線が画面外になる場合があります。「入口から頂上全体が常に見える」と未検証のまま報告しないでください。道中の近いアーチ・石段・中腹の遺構も進行方向の目印として使い、少なくとも複数の場所で目的地の一部を認識できる構図を試します。

遠景を見る目的で探索カメラの比較が必要な場合は、既存の共有Resourceを変更せず、新マップ専用コピーでピッチ-25〜-22度／距離10〜14m程度を**比較候補**として試してよい。既存設定と並べて、主人公・段差・足元・遮蔽物・将来の戦闘範囲が読める画像を提出し、採用はユーザー確認待ちとする。自動ズーム、自由ピッチ、新しい操作、カメラエンジンの全面改修は追加しない。

全景だけでなく、入口・中腹・見晴らし台・頂上の通常プレイ視点で成立することを優先します。画像と同じ全景にするための主人公縮小や、常時数百mを映すカメラは使いません。

## 8. 水彩画の雰囲気と地形の作り方

この画像の、淡い黄緑の草地、青灰〜薄紫の崖、白灰色の石造物、広い空間と明るい寂しさを参照します。既存アート方針書全体を今回まとめて正式採用するものではありません。

- 工程Aでも地形の大きな色面を分け、単一色の平面と階段だけで終了しない。斜面・崖・段丘のシルエット、点在する遺構で画像の場所の関係を表現する。
- 工程Bでは背景の柔らかな色ムラ・テクスチャを段階的に試す。主人公の48px原本、Nearest、フルビルボード、深度補正は保持する。画面全体のぼかしで水彩風にしない。
- 近景の地形、石門、階段、橋、頂上遺跡は3D。画像の向き以外から見た裏面も成立させる。
- 遠景は軽量な山・谷・遺構のメッシュで奥行きを作る。草木の遠景向け簡略表現は可。遠い白化領域は淡い色と形状の欠落で示す視覚試作に留め、白化の進行システムや物語上の原因を実装しない。
- 草・花・岩を一つずつ大量のNode＋Colliderにしない。接地に影響しない装飾は衝突なしとし、必要なら既存環境に合うインスタンス描画を利用する。追加プラグインや外部購入を前提にしない。
- 地形や石造物の再利用部品と配置値を保存し、後で調整できる構成にする。毎フレームの地形生成は行わない。
- 巨大な一枚地形／一つのStaticBody配下に全Meshを集める構成を避ける。現行フェードはヒットしたCollider配下のMeshを収集するため、遮蔽でエリア全体が透明にならないよう、地形を地形形状に合わせた小区画・独立Bodyへ分ける。分割は負荷と表示を見て調整する。
- 現行フェードはBaseMaterial3D系を前提とし、独自ShaderMaterialやnext_passには制約がある。初回は互換性のある材質を優先し、後の水彩表現でもフェード・深度・影の対応を実画面で確認する。
- 小川は軽い水面表現から開始。水の透明描画で主人公・橋・崖の前後関係を壊さない。高負荷な反射や大量の透明表現を初回の必須条件にしない。

## 10. 維持する戦闘・AI・性能

工程Aは敵なし。ただし後工程で既存戦闘を接続できるPlayer／TargetDash／CameraRigの構成を用意し、既存テストで正常動作を維持する。

- 左クリック／J攻撃、右クリック保持／I防御、L切替、通常移動・ジャンプ、連撃、方向入力帰還、帰還後の保持方向移動を維持。
- 主人公・敵の移動速度、カプセル、武器値、踏み込み・帰還の安全性をマップ都合で変えない。
- 雑兵0.4／魔導士0.5の照準確定、実命中／実発射時の地形確認を維持。
- PlanningBudget、分割局所A*、経路保持、キャッシュ、ターゲット表示計画の軽量化を維持。NavMesh全面移行を行わない。
- 水彩の見た目や景観のために、壁・床・天井・崖の安全検査を無効化しない。
- M09の既知課題は引継ぎ台帳へ保持。今回の実マップで支障の出た地点を座標と状態付きで記録し、M09全体を未完了へ戻さない。

工程Cで敵を置く場合の候補は、C付近の平坦な広場に雑兵1体、E付近の十分広い別広場に魔導士1体。最初は別々に確認し、同時配置はその後にする。敵のhome範囲9m／10m、索敵・射線、足場・帰還を満たす配置を実測する。無制限追跡は通常OFF。工程Aの時点では敵を自動追加しない。
