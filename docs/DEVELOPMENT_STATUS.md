## Codexの作業開始ルール
1. `AGENTS.md`、このファイル、対象マイルストーンの仕様・テスト計画を読む。
2. ローカルの実ファイルと `git status` を確認する。文書の記録よりコードと検証結果が新しい場合は差異を報告する。
3. 今回扱うマイルストーン、変更対象、完了条件を宣言してから実装する。
4. 完了時に**このファイルの状態・作業ログ・未解決事項・次の一手**を更新する。ただし未実施テストを「成功」と書かない。
5. 変更ファイル、動作確認結果、未実施テストを報告する。**指示なしでコミット・プッシュしない。**

## 記録のルール
- チャットで会話しただけの案は進捗「完了」にしない。
- 実装済みでも動作確認未了なら「検証待ち」にする。
- 状態を「完了」にしたら、テスト内容・実行環境・関連コミットまたはファイルを根拠欄や作業ログに記録する。
- 仕様の採否は `docs/08_DECISIONS.md`、実装の進行はこのファイルで管理する。
