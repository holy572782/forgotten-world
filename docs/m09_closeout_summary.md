# M09正式終了サマリー・M10への引き継ぎ

2026-11-05／ADR-061。照合基準：ローカルHEAD `91e8218`、Godot 4.7.2の既存実装・Resource・テスト・監査記録。

## 正式な終了状態

**M09：基本戦闘システム完成／追加AI調整は後続マイルストーンへ引き継ぎ。**

ユーザーの正式判断：

> 敵AIの基本機能は成立したため、M09を終了し、M10へ進む。障害物回避の完成度は、実際のゲームマップを作ってから必要に応じて改善する。

基本戦闘の実装と主要な動作確認は完了したものとしてM09を正式に閉じる。坂の角・複雑な地形での停止、追加AIの個別F5未確認、長時間性能などは未解決／未確認のまま後続へ渡す。これらを理由にM09全体を未完了へ戻さず、M10開始の必須修正にしない。2026-10-27の基本戦闘受入（ADR-034）と、その後の追加改善の検査記録を保持する。

M10への移行方針は決定したが、正式な実装範囲・設計・作業は次のChatGPTとの相談で決める。**M10の実装は未着手**。今回の変更は記録のみ。

## FPS改善とM10以降の技術的な維持事項

階段／坂付近のFPS1〜10程度への低下報告を受け、ADR-053・054で経路・攻撃計画を最適化した。性能改善はユーザーF5報告で確認済みとして保持する。M10以降でも以下を維持する。

- PlanningBudget：全敵・主人公の計画処理で共有する1描画フレーム8チェック／約1.2ms。物理問い合わせ1回は不可分で、厳密な全フレーム上限の保証ではない。
- 局所A*の複数フレームへの分割、経路保持、失敗時の再試行待機。現行は半径6m／160地点の局所探索で、大規模迷路の完全探索ではない。
- 攻撃候補の分割・成功／失敗キャッシュ。実発進・実命中には新しい安全確認を残す。
- 地面・全身衝突照会の重複削減、主人公の自動選択／金色マーク用の計画の軽量化、不要な再探索の抑制。
- 新しい地形／敵数では、実Player・マーク・戦闘処理を有効にしてFPS／Physics時間を測る。敵単体の計測だけでゲーム全体の性能としない。

直近の2026-11-04監査では、実main・Player・詳細診断ON、GTX1080／Compatibility、1152×720、60FPS上限／物理60Hz、各75tick warmup＋約3秒の18配置で、平均FPS59.924〜60.076、Physics p95最大9.404ms、単発最大35.497msを記録した。これは既存の計測結果の引用であり、今回の再測定ではない。**FPS60はこれまでのF5・計測条件での結果であり、すべてのマップ・敵数・長時間での性能保証ではない。**

詳細：[ADR-053監査](m09_pursuit_performance_audit.md)、[ADR-054監査](m09_work_budget_audit.md)、[最新監査・条件](m09_enemy_ai_policy_audit.md)、[既存生データ](measurements/m09_enemy_ai_policy.json)。

## M10の相談に持ち込む候補

テストマップ中心の開発から、実際の探索フィールドでのゲーム制作へ進む方針。ユーザーが挙げた『ゼノギアス』の立体的な探索、『風ノ旅ビト』の印象的な遠景という参照意図を、探索の方向性として記録する。48×48ドット絵キャラクターと3Dフィールド、シンプルで直感的な操作、歩いて探索する楽しさと記憶に残る冒険体験を重視する。

最初は小規模な探索エリアで、移動・カメラ・戦闘・地形表現を統合して確認する案を候補とする。これは地形・美術・物語・敵数・制作順の正式決定ではない。既存工程表の「洞窟・小ボス・10〜15分デモ・大型敵の視認性」も以前の計画として保持し、今回それらを一括で実装する承認とは扱わない。正式な範囲は次のChatGPTとの相談で決める。アート方針書の提案・レビュー待ちも維持する。
